# What 1.0.0 means

**Date:** 2026-09-04
**Status:** agreed, not started
**Version at time of writing:** 0.6.0 — 987 tests, 1,399 archived matches, 85.7% line coverage

## Why this exists

The repository had no milestone and no roadmap. The only written reference to 1.0 was
CONTRIBUTING's versioning table, which says a breaking change to config keys, the archive
layout or CLI arguments is a **minor** bump while pre-1.0 and a **major** one after. So
1.0 already had a contractual meaning here before it had a definition, and work was being
picked from the issue backlog without knowing whether any of it was on the path.

This document is that definition. It is deliberately finite: every condition below can be
checked rather than argued.

## The four conditions

1.0.0 ships when all four hold and their proofs are recorded.

### 1. The contract is stable

Every config key, CLI verb and archive file has been reviewed and deliberately blessed.
After 1.0, changing any of them is a major bump.

The surfaces as they stand:

| kind | members |
|---|---|
| config keys | `LogPaths`, `CardDbPath`, `ArchiveDir`, `OutputDir`, `LocalPlayerUserId`, `OpenAfterBuild`, `SuggestDeckRotation`, `MaxArchivedMatches`, `ManaLedger` |
| CLI verbs | `capture`, `build`, `stats`, `watch`, `keep`, `unkeep`, `collection`, `why` |
| archive files | `raw/<matchId>.json.gz`, `index.json`, `logs.json`, `inventory.json` |
| config files | the shipped `mtga-pbp.defaults.json` and the user's `mtga-pbp.json` |

**Proof:** a committed table, one row per surface, each marked keep or change with a
reason.

### 2. The transcript is complete

Every annotation type Arena emits is either narrated or recorded in CONTRIBUTING's
"Things deliberately not done" with evidence. No type is simply unexamined.

**Proof:** a CI guard fails the build when `stats` reports an unhandled annotation type
that is not a documented decision — the same shape as the existing skipped-tests guard,
which fails when the set of tests that cannot run on CI grows.

This is the condition that makes 1.0 finite. Completeness becomes a state the tool can
report rather than a judgement someone makes.

A guard rather than a release-day check, decided 2026-09-04. Checking once at the tag
would be true on the day and quietly false a month later: new Arena sets bring new
annotation types, so an unexamined type would arrive silently and 1.0's own claim would
rot without anyone noticing. A guard turns that from a thing to remember into a thing
that fails.

### 3. It is ready for strangers

- #65 (`aria-pressed` silences a button under the pointer) is fixed.
- #1 is closed: an NVDA pass with no open reader bug.
- The published release zip runs on a machine with no repository and no .NET SDK.

**Proof:** both issues closed, and the clean-machine run written down as a comment on #1
with what was tested — including the failure paths, not only the happy one.

### 4. It is proven at scale

Index load and search measured at today's 1,399 matches and at synthetic 3,000 and 5,000.
The budget is set from those numbers rather than guessed at beforehand — "measure first,
decide after" — and once set it is committed to in writing, so a later miss is a release
blocker rather than a discussion.

The index is one HTML document holding every match: 2.9 MB at 1,399, roughly 2.1 KB per
match, which projects to about 6.3 MB at 3,000 and 10.5 MB at 5,000. Whether that is a
problem is the thing being measured rather than assumed.

**Proof:** the measurement recorded and the budget met — either because the page already
meets it, or because the index changed shape until it did.

Size and time-to-interactive are the gate. Search latency is measured where cheap and
does not block.

## Explicitly out of scope

**#137** (opponent-only cards on the index) and **#138** (a digest export sized for a chat
window) are 1.1 material.

Both are new capabilities rather than gaps. The transcript is not silent about anything
without them, so under condition 2 they do not gate the version. This is the line that
keeps 1.0 reachable instead of receding.

## Sequencing

Two investigations run first, because either can change what the rest of 1.0 contains.
Discovering mid-execution that the index needs re-shaping — after the index work has
already landed — is the expensive ordering.

### Investigation A — surface audit

Walk every surface in condition 1. For each: is the name right, is the shape right, would
freezing it be a regret? Grounded in evidence where it exists; the config-file split
already has a scar to read in #134, where unzipping an upgrade over the install folder
replaced the user's own settings.

Output: the table condition 1 asks for. Anything marked "change" becomes a pre-1.0 task
and must land before the tag.

### Investigation B — scale measurement

Measure the index at 1,399, 3,000 and 5,000 matches. Metrics, in priority order: file
size, time to interactive, then keystroke-to-result latency in the search box.

Synthetic runs write to a scratch output directory. They never touch `out/`, and they
never touch the archive — it is the durable source of truth and every rebuild re-derives
from it.

Output: the numbers, and a recommendation on whether #139's keyed row swap, search
haystack trim and input debounce carry it, or whether a single-document index has a
ceiling that has already been reached.

## Handoff checklist for tasks 7 and 8

### Task 7 — NVDA pass

The last two passes were 2026-08-21. This targets what has changed since, plus the one
known weak spot.

New line types, none of which existed at the last pass:

- `You keep 3x Plains · 2x Hare Apparent · …` — does the middle dot read as a separator
  or get swallowed, and does `3x` read as "three" or "three ex"?
- `You end holding …` at a game's end.
- `You pay in 1st Main: {W}{W}{C}` — only with `ManaLedger` on. The mana symbols are the
  risk.
- `creates Zombie Army, which immediately dies`.
- `You activate Cavern of Souls` — a changed verb across roughly 805 archive lines.

Then the known unsolved one: hover-reading of the `.vh` twins (#61). A pass that confirms
it is still the only gap is a valid result.

Then the index, not only a game page. Different markup, and it is the first thing anyone
opens.

### Task 8 — clean-machine install

A fresh Windows user account is enough; a separate machine is not required. No
repository, no .NET SDK.

1. Download the release zip from the GitHub release page — the published artifact, not a
   local `dist/`.
2. Unzip and run `mtga-pbp.exe`.
3. Does it find `Player.log` unaided? Does it find the card database?
4. Does the report open by itself? `mtga-pbp.defaults.json` ships `OpenAfterBuild: true`
   for exactly this case.
5. Read the console output as a stranger would. Does it say where things went?
6. The failure paths, which matter more than the happy one: Arena installed but never run
   so there is no log, and an empty archive.
